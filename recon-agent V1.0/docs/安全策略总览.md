# recon-agent V1.0 安全策略总览

> 本文档汇总项目中**全部安全性策略**，按防御层级组织。
> 每条策略标注代码落点与测试覆盖，`# HARD:` 标记在源码中可全局 grep 审计（当前 267 处）。
> 配套：知识骨架（调试案例）· 项目说明书（架构）· 使用说明书（操作指南）

---

## 总览：五层防御模型

```
第 1 层 目标准入    —— 你能扫谁（合规/范围/红线）
第 2 层 行为门控    —— 你能做什么（级别/确认/签名/逐项）
第 3 层 执行约束    —— 你怎么做（限速/单线程/失败即停/UA/沙箱）
第 4 层 数据可信    —— 结论从哪来（证据/去重/矛盾/一致性/否定证据）
第 5 层 审计追踪    —— 你做了什么（哈希链/签名文件/测试隔离）
```

每一层的绕过都会被下一层拦截。**没有任何单一入口可以跳过全部五层。**

## 第 1 层 · 目标准入（你能扫谁）

### 1.1 绝对红线（任何模式/参数/确认不可解锁）

| 红线 | 规则 | 代码 |
|---|---|---|
| 政府/军事域名 | `.gov` `.mil` `.gov.cn` `.mil.cn` 后缀匹配绝对拒绝 | security/stealth.py::allowed_target |
| 云元数据地址 | `169.254.0.0/16` 链路本地绝对拒绝 | 同上 |
| RFC1918/内网 | `10.x` `172.16-31.x` `192.168.x` `127.x` 默认拒绝（`--lab` 可解锁自有环境） | 同上 |
| localhost | 默认拒绝（`--lab` 可解锁） | 同上 |

> 测试覆盖：`test_stealth.py::test_allowed_target_rejects_private_and_protected`、`test_golden.py::test_golden_13_gov_mil_not_unlockable_in_any_mode`

### 1.2 授权声明

| 场景 | 要求 | 代码 |
|---|---|---|
| CLI 交互模式 | `--authorized` 或终端输入 `yes` | cli/main.py::_confirm_authorization |
| CLI batch 模式 | 必须加 `--authorized`，否则拒绝执行 | cli/main.py |
| MCP 模式 | `--authorized-for <域名>` 必填，否则拒绝启动 | server/mcp_server.py |
| L1 端口扫描 | 上述基础上需一次确认（交互 `yes` / MCP `--allow-l1`） | gate/scan_gate.py::request_level_1 |
| L2 深度探测 | 三次独立确认 + 签名文件 + 逐项确认 | gate/scan_gate.py |

### 1.3 范围锁定（代码层硬拦截，不依赖 Prompt）

| 规则 | 实现 |
|---|---|
| 仅主域及其子域可扫 | security/stealth.py::is_in_scope（`candidate == main or candidate.endswith("." + main)`） |
| 关联资产/C 段仅记录不扫描 | cli/pipeline.py + collectors/asset_expander.py |
| IP 目标仅精确匹配（同 C 段其他 IP ≠ 范围内） | 同上 |
| 注册表五道守卫链统一执行 | tools/registry.py::execute（Schema→合规→范围→门控→隐蔽修正） |

## 第 2 层 · 行为门控（你能做什么）

### 2.1 L1 门控（一次确认）

- 启动参数 `--profile stealth` / `--level 1` 即为显式确认（batch 模式可用）
- 交互模式下 gate 自动追问（`request_level_1`）
- MCP 模式需启动参数 `--allow-l1`

### 2.2 L2 门控（三次独立确认 + 签名 + 逐项）

| 机制 | 规则 | 代码 |
|---|---|---|
| 三次独立确认 | 步骤 1: `CONFIRM 2` · 步骤 2: 目标精确字符串 · 步骤 3: `I UNDERSTAND AND AUTHORIZE` | gate/scan_gate.py::request_level_2_step |
| 通用词无效 | `y/yes/确认/是/ok` 一律拒绝 | 同上（GENERIC_YES 集合排除） |
| 签名文件 | SHA256 + 时间戳 + 操作者指纹 → `auth/<target>.sig` | gate/scan_gate.py::unlock_level_2 |
| 会话有效 | 签名仅当次进程有效，跨会话需重新确认 | 构造时不读取旧签名 |
| 逐项确认 | 每个具体动作执行前单独确认（不可批量 yes） | gate/scan_gate.py::confirm_step |
| abort | 任意环节输入 `abort` 立即退回 L0 且不可撤销 | gate/scan_gate.py::abort |
| 非交互禁 L2 | `--batch` / 无 TTY / MCP 模式 **永久禁止** L2 | 全路径检查 |
| `--auto-confirm` | 仅限授权测试目标的自动化验证（审计留痕） | scripts/aggressive_l2.py |

### 2.3 级联语义

- `--level N` 自动包含 0..N-1 级（高级别包含低等级）
- 门控语义不变：L1 需确认，L2 需三次解锁——级联不降低确认标准
- `--auto-confirm` 仅注入 L2 确认码，**不注入** L1/L0 的跳过（L0 本身无需确认）

## 第 3 层 · 执行约束（你怎么做）

### 3.1 隐蔽性强制（security/stealth.py）

| 约束 | 实现 | 级别 |
|---|---|---|
| 单线程 | 每工具实例 Semaphore(1) | L0/L1/L2 |
| 请求间隔 | L0: 1-2.5s · L1/L2: 3-10s（随机） | 全级别 |
| 仅 TCP Connect | `-sT --max-rate 1 --max-parallelism 1` 强制注入 | L1/L2 |
| 禁用扫描类型 | `-sS -sU -A -sV --version-all` 自动剔除 | L1/L2 |
| 时序模板禁用 | `-T4 -T5` 自动剔除 | L1/L2 |
| 浏览器 UA | Chrome/Firefox/Safari 随机，禁自定义扫描器 UA | 全级别 |
| 失败即停 | ConnectionRefused=答案（继续）；Timeout=失败（**立即停止**） | L1/L2 |
| 并发上限 | 绝对 ≤2（默认 1），超限自动修正 | 全级别 |

### 3.2 沙箱三层（scripts/sandbox.py）

| 层 | 机制 | 失败后果 |
|---|---|---|
| AST 黑名单 | 禁 os/sys/shutil/subprocess/importlib/ctypes/requests 模块；禁 eval/exec/compile/__import__/open；禁文件写/网络 POST | 拒绝执行 |
| Bandit 扫描 | HIGH 级发现 → 拒绝；bandit 缺失 → 拒绝（三层缺一不可） | 拒绝执行 |
| 运行时隔离 | Docker（断网/只读/降权/内存限制）；缺 Docker → 宿主机直跑 + 超时强杀 + 审计告知 | 超时 kill |

### 3.3 并发边界（并发与隐蔽的平衡）

| 操作 | 并发策略 | 约束 |
|---|---|---|
| DNS 5 类型查询 | `asyncio.gather` 并行 | 仅触碰公共解析器，不影响目标 |
| 被动 DNS 4 源 | `asyncio.gather` 并行 | 仅访问第三方 API |
| 多主机指纹 | `Semaphore(3)` 跨主机并行 | 不同主机并行，每主机仍限速 |
| 同一主机路径枚举 | **串行**（3-10s 随机延迟） | 同一目标必须模拟人类节奏 |
| 同一主机端口扫描 | **串行**（3-10s 随机延迟） | 同上 |

### 3.3 HTTP 出口统一安全检查点（tools/builtin/webfetch.py）

全部工具的出站 HTTP 请求统一走 `http_get()`，消除 5 处重复逻辑。该模块强制执行：

| 约束 | 实现 |
|---|---|
| scheme 白名单 | 仅允许 `http://` `https://`，禁止 `file://` `ftp://` 或自定义 scheme |
| 浏览器 UA | Chrome/Firefox/Safari 随机，禁自定义扫描器 UA |
| 4xx/5xx 答案 | HTTPError 作为有效指纹答案（WhatWeb 式），非连接失败 |
| IP 目标证书跳过 | IP 目标自动 `CERT_NONE` 重试一次（WhatWeb 同款），evidence 标注 |
| 响应体截断 | ≤200KB（防内存炸裂），泄露嗅探可扩展至 100KB |
| 错误收敛 | 连接失败 → `(0, {}, "")`，永不抛异常到调用方 |

### 3.4 泄露嗅探（tools/builtin/leak_signatures.py）

内容级泄露分析（不止看状态码，分析响应体内容）：

| 签名 | 级别 | 示例 |
|---|---|---|
| 私钥文件 | High | `-----BEGIN RSA PRIVATE KEY-----` |
| AWS Access Key | High | `AKIA...` |
| Git 仓库元数据 | High | `ref: refs/heads/` |
| API 密钥/令牌 | High | `api_key=...` |
| 数据库连接串 | High | `mysql://root:pw@...` |
| 目录列表 | Medium | `Index of /` |
| phpinfo 页 | Medium | `phpinfo()` |
| JWT 令牌 | Medium | `eyJ...` |
| Actuator 内容 | Info | `_links` JSON |
| PHP 路径泄露 | Low | `Warning: ... in /` |

### 3.5 并发边界（并发与隐蔽的平衡）

| 操作 | 并发策略 | 隐蔽约束 |
|---|---|---|
| DNS 5 类型 | `asyncio.gather` 并行 | 仅触碰公共解析器 |
| 被动 DNS 4 源 | `asyncio.gather` 并行 | 仅访问第三方 API |
| 多主机指纹 | `Semaphore(3)` 跨主机并行 | 不同主机并行，每主机仍限速 |
| 同一主机路径枚举 | **串行** | 同一目标必须模拟人类节奏 |
| 同一主机端口扫描 | **串行** | 同上 |
| 同一主机深度指纹 | **串行** | 同上 |

> 并发边界：不同目标/不同第三方 API → 可并行；同一目标 → 必须串行限速。
> 实测：DNS 55→25s（-55%）· 被动源 20→10.6s（-47%）· 指纹 63→21s（-67%）。

### 3.6 有界约束

| 维度 | 上限 | 理由 |
|---|---|---|
| 端口 | ≤20/次 | 禁无差别全端口扫描 |
| 路径 | ≤80/次（合并后） | 禁目录爆破 |
| 子域字典 | ≤600 词 | 禁子域爆破 |
| 深度指纹 | ≤10 GET/台 | 限请求总量 |
| 递归 | ≤10 子域 × 1 层 | 防无限递归 |
| 并发指纹主机 | ≤3 | 控制总出站速率 |

## 第 4 层 · 数据可信（结论从哪来）

### 4.1 证据绑定（hallucination/evidence.py）

| 机制 | 规则 |
|---|---|
| evidence | 每条 ToolResult 必须携带来源清单（URL/Header/签名表名） |
| source_hash | 响应体 SHA256 前 64 字节 |
| confidence | 置信度 ≤0.7 的结论标注 `[未确认]` |
| degraded | 降级模式自动下调一档 + 报告标注 |

### 4.2 矛盾检测（hallucination/contradiction.py）

- 同主体同属性多来源冲突 → `[冲突，需人工核实]`
- **保留双方**，禁止模型二选一

### 4.3 一致性校验（hallucination/consistency.py）

- 报告生成前比对结论与证据登记簿
- "报告有、证据无" → 标 `[无证据]`（CI 可配置阻断）

### 4.4 否定证据（knowledge/cve_base.py）

- CVE 查不到 → 硬输出 `"未收录"`，**禁止编造编号**
- 快照 SHA256 签名校验，不匹配拒绝加载（防投毒）
- 快照缺失 → 硬输出 `"不可用"`，不推测

### 4.5 有界诚实

| 场景 | 行为 |
|---|---|
| 指纹未检出 | 标注"未检出"，不推测 CMS |
| 空结果 | 输出"未检出"，不填补 |
| 端口未扫 | 标注"未探测（需 L1）"，与"扫过无开放"严格区分 |
| 子域 0 命中 | 标注"0 命中（CT 源受限）"，不据此认定"没有子域" |

## 第 5 层 · 审计追踪（你做了什么）

### 5.1 审计哈希链（utils/logger.py）

| 机制 | 规则 |
|---|---|
| 链式哈希 | 每条记录 `prev` + `hash`（SHA256），篡改/删除可检出 |
| 实时读尾 | 每次写前读取文件尾哈希（不用进程缓存，多进程安全） |
| 验证 | `verify_audit_chain()` 逐条校验哈希 + 链连续性 |
| 测试隔离 | conftest autouse 强制测试审计走 tmp_path，**生产日志只由真实作业写入** |
| 轮转 | 链断裂/污染后轮转存档（保留证据）+ 新链起链 |

### 5.2 签名文件

- L2 解锁后生成 `auth/<target>.sig`（SHA256 + 时间戳 + 操作者指纹）
- **仅当次会话有效**，跨会话需重新确认
- 内容不可伪造（操作者指纹绑定）

### 5.3 授权背景

- `--note` 参数将授权说明写入审计 `l2_authorization_context` 事件
- 谁授权、什么关系、什么范围——全部可回溯

### 5.4 测试隔离（tests/conftest.py）

- autouse fixture 强制所有测试的审计走 tmp_path
- **生产 audit.log 只由真实作业写入**（已在 QA 中实测验证）

### 5.5 WhatWeb 插件架构安全（tools/techniques/）

- 插件仅声明 paths + analyze，引擎统一限速抓取分发
- 新增插件零改动引擎代码——扩展安全性靠签名表审计而非代码审查
- 插件产出的 Finding 必须带 source（evidence 追溯），置信度与来源强制绑定

- autouse fixture 强制所有测试的审计走 tmp_path
- **生产 audit.log 只由真实作业写入**（已在 QA 中实测验证）

## 第 6 层 · 输入安全

### 6.1 目标参数校验

| 校验 | 实现 |
|---|---|
| 域名/IP/URL pattern | Pydantic Field(..., pattern=r"^[\w\.\-/:]+$") |
| 端口范围 | ≤20（L1），≤80 路径（L2） |
| IPv6 | 裸地址/括号形式均正确解析（本轮修复） |
| 尾点归一 | `example.com.` → `example.com` |
| 大小写 | 统一小写处理 |

### 6.2 出站 URL 白名单

- 全部 6 处 HTTP 出口统一加 `url.startswith(("http://", "https://"))` 守卫
- 禁止 `file://` `ftp://` 或自定义 scheme 出站

### 6.3 LLM 输出安全

| 层 | 机制 |
|---|---|
| Schema | Pydantic 严格校验（pattern/Literal/范围），失败回填 LLM 修正 |
| 语义 | 合规/范围/门控/隐蔽四道检查（代码层，非 Prompt） |
| XML 协议 | ET 解析 + ParseError 显式捕获；expat 内置 billion-laughs 缓解 |
| 工具结果 | 结构化 JSON 输出（非原始文本直传 LLM） |

## 第 7 层 · 降级安全（故障不崩溃）

| 故障场景 | 行为 |
|---|---|
| nmap 缺失 | → builtin_socket 降级（标注 [降级模式] + 置信度下调） |
| httpx 缺失 | → builtin urllib 降级 |
| DoH google 超时 | → alidns 备源直连 |
| DoH 全挂 | → socket.gethostbyname 兜底 |
| crt.sh 不可达 | → certspotter 备源 |
| CT 全挂 | → 子域枚举降级为空（显式记录，不推测） |
| LLM 不可达 | → 离线模板报告（不崩溃） |
| bandit 缺失 | → 沙箱拒绝执行脚本（三层缺一即拒） |
| Docker 缺失 | → 宿主机降级隔离 + 审计告知 |
| 状态文件缺失 | → 显式报警，禁止静默出空清单 |
| Wayback 不可达 | → 采集失败显式记录 |
| pytest tmp 锁 | → --basetemp 切换或清理 |
