# 发现复核与反证

## 目标

让每项安全发现可追溯到具体证据，并主动检验误报、替代解释与影响范围。

## 复核步骤

1. 通过 `evidence_search` 找到当前授权目标的证据，再用 `evidence_get` 或 `artifact_read` 读取必要内容。
2. 核对来源、时间、目标、工具状态、响应码、截断/降级及证据哈希。
3. 区分候选、观测和验证；静态线索、第三方情报或 HTTP 200 本身不能确证漏洞。
4. 只在授权范围与门控允许时，以最小只读请求复核；不做写入、利用链或破坏性验证。
5. 使用 `recon_finding` 保存结论和证据引用，并记录反证与未解决问题。

## 报告

说明影响、可复现依据、置信度和限制。证据不足时保持候选/观测状态，不能因工具失败推断为安全，也不能把推测表述为已验证漏洞。
